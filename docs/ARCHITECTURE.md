# Архитектура Liftorg B2B

## Стек
- FastAPI / Python
- React для основного каталога
- server-rendered страницы для резервного интерфейса, карточки, опросника и части админки
- SQLite на тестовом контуре; целевой production — PostgreSQL
- Docker Compose
- Nginx reverse proxy

## Поток данных
1. Исходные Excel/DOCX/PDF заказчика задают технические данные и правила.
2. Каталог нормализуется в записи исполнений.
3. Интерфейс группирует исполнения по модели.
4. Подбор работает по конкретным исполнениям и возвращает PASS / UNKNOWN / FAIL.
5. Пользователь выбирает конкретное исполнение.
6. `product_id` выбранного исполнения используется в сравнении, калькуляторе, опросном листе и заказе.

## Медиа
Приоритет наследования: execution → model → family → legacy fallback.
Persistent директории живут вне Docker image.

## Роли
- Покупатель: финальная цена и пользовательские технические параметры.
- Сотрудник: полная калькуляция и внутренние параметры.
- Производитель: собственная номенклатура/цены (развитие роли продолжается).
- Администратор: управление данными, атрибутами, медиа и заявками.
