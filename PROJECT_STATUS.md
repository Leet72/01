## Подтверждённые замечания инженера — 27.08.2026 (v4.4.4)

В инженерном опроснике обязательны следующие правила:

1. Пользовательские подписи и подсказки должны быть однозначными и инженерно понятными; рядом со сложными параметрами приводится пример или пояснение, что именно измерять/выбирать.
2. Пользовательский интерфейс использует систему СИ. Футы, фунты и дюймы из оригинального американского TDNA Survey не используются как единицы ввода. Геометрические размеры задаются в мм, длины — в м, масса — в кг, ускорение — в м/с².
3. Поле 208–230 / 460–480 называется «Выходное напряжение привода, В», а не «мощность».
4. Для параметров, завязанных на эскизы Torin, интерфейс явно показывает ссылку «См. рис. N».
5. Каждый эскиз в опроснике увеличивается по клику в полноэкранном lightbox; закрытие — кнопкой, кликом по фону или Esc.
6. Неоднозначное поле «Расположение существующей закладной балки под лебёдку» заменено понятным выбором схем A–E из Torin Illustration 3 с пояснением.
7. Трос Боудена называется «Устройство дистанционного растормаживания». Он находится в инженерном опроснике рядом с длиной кабеля энкодера, а не в калькуляторе. Значения: «Не требуется», «8 м (стандарт)», «10 м», «12 м». Правило действует как для машинного помещения, так и для MRL.
8. Опросник остаётся необязательным: пользователь может сразу выбрать «Заказать лебёдку» и отправить короткий коммерческий запрос.

## v4.4.6 — медиабиблиотека оборудования

Реализована управляемая медиабиблиотека без привязки к правке кода.

Правила наследования медиа:

1. `execution` — конкретное исполнение имеет наивысший приоритет;
2. `model` — если у исполнения нет своего фото, используются материалы модели;
3. `family` — если у модели нет собственного материала, используется семейство производителя;
4. старое `image_ref` остаётся безопасным fallback для обратной совместимости.

Одна модель/семейство/исполнение может иметь несколько материалов. Поддерживаемые типы: `photo`, `drawing`, `document`. Для фото можно назначить основное изображение и порядок сортировки. Основное фото автоматически используется в каталоге, карточке и сравнении.

Добавлена таблица SQLite `media_assets` со связями `manufacturer / family / model / product_id`, типом материала, URL, названием, признаком основного фото и сортировкой. При первом запуске существующие изображения из `image_ref` и сохранённые семейные файлы `/static/winches` автоматически регистрируются в медиабиблиотеке.

Администратор получает страницу `/admin/media`, где можно загрузить JPG/JPEG/PNG/WEBP/GIF/SVG/PDF, выбрать уровень привязки, тип материала, основное фото и порядок. В карточке позиции из `/admin` добавлена ссылка `Медиа`.

Публичный API `/api/products/{id}` теперь отдаёт `media`, `media_family`, `primary_image`; `/api/products/{id}/media` возвращает разрешённую галерею. Карточка оборудования показывает галерею `Фото / Чертежи / Документы`.

Важно для обновлений: вместе с БД необходимо сохранять оба каталога `/app/static/winches` и `/app/static/media-library`. Загруженные файлы не удаляются физически при удалении привязки из БД, чтобы не разрушать исторические snapshots заявок.

## v4.4.9 — Explicit Execution Selector / различия исполнений

Подтверждённое UX-замечание заказчика: когда одна модель содержит несколько исполнений, пользователь должен однозначно понимать, как переключать исполнения и чем они отличаются.

Реализовано:
- вся строка исполнения кликабельна;
- добавлен явный radio-индикатор выбора и бейдж «Выбрано»;
- выбранная строка визуально подсвечивается;
- текст прямо сообщает, что выбранное исполнение используется для расчёта, опросного листа и заказа;
- таблица автоматически показывает только те нормализованные технические характеристики, значения которых реально различаются между исполнениями данной модели;
- различающиеся ячейки визуально выделяются;
- управление доступно мышью и клавиатурой Enter/Space;
- при переключении заново загружается полный product record конкретного `product_id`, поэтому медиатека, технический паспорт, сравнение, калькулятор, опросник и заказ работают с выбранным исполнением.

Контрольный пример из текущей БД: модель `WE 06-630-100(400)` содержит исполнения `#360` и `#395`. Их видимые базовые параметры совпадают, но масса различается: `280 кг` против `310 кг`. В v4.4.9 таблица автоматически показывает именно столбец «Масса», не заставляя пользователя искать отличие вручную.
